# Service operations implementation

The enterprise workspaces expose these commands in the browser and at `POST /api/openservice/enterprise/{area}/global`. A write that takes a revision expects the revision last read. The worker must be enabled for scheduled imports and maintenance.

| Workspace | How to use the workflow | Current boundaries |
|---|---|---|
| Connector packages | Install a GET package with a string cursor, bind an environment, and use `schedule_delta`. Inspect its checkpoint, review `rejected_changes`, then use `correct_change` with that cursor and a corrected record. The receipt preserves the original row. Migration 100 carries forward existing accepted receipts. | Each page commits its receipts and checkpoint together. A poll accepts 250 records and a cycle accepts 256 pages. A changed payload under an existing cursor or a row without a usable cursor stops the page for investigation. The provider-effect audit reader and live tenant requirements are described in [provider qualification](enterprise-platform-workflows.md#qualification-still-required). |
| Decision workflows | Publish a purchase action by mapping the approved row's model, quantity, unit cost, useful life and residual value. Enter its ID in a list policy. Start the policy on a requisition or authorized HR case with named input records. Distinct owners review their own rows. Fulfill approved rows, or pause purchasing with a reason. Lift the hold and retry a failed row. Open the returned order in Purchasing for approval and partial receipt. | The run pins the action, its field bindings, inputs and version. Purchase and catalog fulfillment are supported action types. HR access is checked at intake. Purchasing retains its own supplier and finance approval. |
| Federated service maps | Register a mapped component and on-call roster with `define_objective`. Assign a staff identity to each location with `probe_identity`. Run a probe at each location at the configured interval. Two failures in the same interval create a critical incident. An independent health check at each location distinguishes probe failure. Use `objective_report` for samples and the CAB agenda for the component's budget. | The rolling 30-day report separates unknown intervals and consumed downtime. Both locations must report for an interval to count. The current interval is excluded from the budget until complete. Existing site-monitor bindings determine customer cases. A release owner closes the resulting outage through the existing recovery workflow. |
| Employee request assistant | Configure the native intent, offering and published article. Bind an approved HTTP source using `index_external`, mapping external group names to local group IDs. The document is JSON with `title`, `body`, `version`, and `allowed_groups`. Search, selection and confirmation check current local membership, connector origin, upstream access and document contents. | A changed or unavailable document fails closed until the source is available and the index refreshed as needed. Ranking is lexical. The evaluation uses three eligible offerings and one restricted policy. [Results and missed questions](external-policy-search-results.json) |
| Supplier governance | After a passing assessment, the assigned legal owner offers a dated price schedule, currency and obligations to a designated supplier account. The supplier can request revisions or accept. Finance records the signature reference for the accepted version. Use `agreement_history` to reconstruct proposals and signatures. Legal can record a renewal or termination notice. Use the dated invoice form in Purchasing to compare an invoice with the signed terms in force on its pricing date. | OpenService records authenticated decisions and the signed reference. The signature content and verification remain with the signing provider. Contracts use a supplier-level schedule with model-specific prices. Renewal terms go through a new offer and finance acceptance. |
| Project spend | Create an epic for a project with approved quarterly funding, then add stories for different teams and name their predecessors. Use `schedule_sprint` with dates and a minutes-per-point estimate for each group. The calendar calculation accounts for exceptions and other project reservations. Ship a story against a deployed release. Closing a sprint returns unfinished work to the backlog and preserves the plan and outcomes. | Dated sprints span at most 31 days within one quarter. Manual point budgets are also supported. The operator links the successful deployment. |
| Supplier privacy assessments | The application owner records the supplier, purpose, data categories, retention, sensitivity, and supplier question. The supplier sees its assigned question. Sensitive processing requires the supplier's independent security reviewer. The reviewer can assign remediation and review the submitted correction. Rescreen a changed purpose and reopen a previous revision. | Screening uses the declared sensitivity and an enrolled supplier. Each revision preserves the evidence available at that decision. |
| Certificate inventory | Import the observed DER certificate as base64, its endpoint, source, service CI and owner. The SHA-256 fingerprint identifies the certificate across sources. Discovery within 30 days of expiry opens a renewal request. Register the replacement, then have an independent observer report what each endpoint serves. The request closes after all endpoints match. | The supplied collector validates the TLS trust chain and hostname. Discovery and deployment happen on authorized endpoints. The exercise issues two certificates from a local test CA and changes the two TLS listeners independently. |
| Territory dispatch | Create a recurring maintenance plan for a registered customer site case, with a stockroom, part model, required skills, technician, UTC start and duration. The worker creates one native field task per occurrence when it enters the next 24 hours, then tries to assign the technician and reserve serialized stock. A dispatcher can inspect the shortage and replan the visit. The technician uses the existing pickup and offline worksheet. | The site must be represented by a customer case. Occurrences recur at whole-day UTC intervals. Stock, installed-asset custody and mobile replay use the field service records. |
| Walk-up service desks | Configure desk capacity and slot length. Employees can book or join a queue, check in and read their own visit. Staff can transfer a waiting visit, mark a missed appointment, and claim one visit under the transaction lock. Completing a swap returns the original asset, issues the replacement and completes the native request. Compare desk wait times and outcomes using `desk_compare`. | An appointment starts on a UTC slot boundary. Wait time is measured from arrival to claim. The supported completion journey is a serialized equipment swap. |

## Run a location probe

Run `python3 scripts/service-probe.py location.json --every-minutes 5` at each location for a five-minute objective. Omitting the interval runs a single check. For `probe_sample`, provide the OpenService HTTPS origin, an environment variable containing the Authorization header, the objective ID, the registered location name, the target HTTPS URL, and an independent location health URL.

```json
{
  "operation": "probe_sample",
  "openservice_origin": "https://openservice.example.org",
  "auth_env": "PROBE_AUTHORIZATION",
  "objective_id": "0123456789abcdef0123456789abcdef",
  "location": "east",
  "endpoint": "https://service.example.org/health",
  "location_health_url": "https://location-health.example.org/ready"
}
```

An unavailable control endpoint yields `probe_error`. For certificate verification, use `verify_certificate`, `fingerprint`, `endpoint` and the renewal's current `revision` with the same OpenService connection settings. An optional `ca_file` supplies the monitored endpoint's trust roots. A separate `openservice_ca_file` configures trust for the reporting connection. The collector sends authorization only to the configured OpenService origin.

## Reproduce the acceptance journeys

Use the JDK required by the repository's Maven enforcer. The SQLite and PostgreSQL workflows exercise volume imports, source revocation, procurement, budgets, supplier privacy, sprint delivery, renewal, maintenance and walk-up custody. The Chromium test `BrowserTest#walkupAndActionAuthoring` exercises action creation and an employee desk visit. The certificate exercise also runs independently with `python3 scripts/test-certificate-deployment.py`.

For the search comparison, the test registers expected offering, article, owner and restricted article before scoring the 100 questions. The simulated employee confirms the top suggestion only when it has a unique highest score. Failed and ambiguous retrievals go to the service desk. The gold label is used only for scoring. Both configurations run the same questions through native search, confirmation and handoff. The measured latency is the application's recorded processing time. The local ranking path makes zero model calls.

## Verification on 20 November 2026

The full Java regression run passed 1,943 distinct tests. Ten additional recovery and authorization tests passed against the same production classes. The updated maintenance, desk, import and service-objective journeys also passed on both databases. The combined JaCoCo report covered 19,671 of 19,671 lines, 16,101 of 16,101 branches and 1,586 of 1,586 methods. Maven packaged the application and passed its coverage check using the combined execution data. Chromium passed the purchasing-action authoring and walk-up journey, and all four browser scripts passed the repository's line, branch and function checks. All 16 Python tests passed. The location probe and certificate collector covered all 75 executable statements and 14 branches.

The import exercise processed 10,000 distinct changes. SQLite terminated the JVM inside an uncommitted page. PostgreSQL rolled back the interrupted transaction. Both recovered through a rate limit and overlapping pages, then corrected the rejected row. The two-location outage exercise produced one page and two customer cases. The local certificate authority exercise left one endpoint on its old certificate and kept renewal open until both endpoints served the replacement.

On the same 100 authored employee questions, verified outcomes increased from 44 to 81. For the 75 eligible requests, correct citations increased from 19 to 56. Both configurations assigned the 25 expected handoffs correctly. The evaluation observed zero unauthorized citations and incurred zero model charges. External-source p95 application processing time was 3 ms on SQLite and 20 ms on PostgreSQL for the published run. The [paired comparison](external-policy-search-results.json) includes missed questions and outcomes.

Live credential rotation and audit qualification for Entra and Jira remain open. The accepted inputs are a designated test group and member, a designated Jira issue and transition, credential binding references, and read access to the corresponding provider history.
