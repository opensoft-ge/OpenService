### Round 4 — dependent team work and enforced parent completion

Selected OS-N18D-04, WS7 / OS-PARITY-02. Existing fulfilment supports one group task per catalogue request, while arbitrary incident/problem/change and configured cases lack coordinated task sets, finish-to-start dependencies and a shared parent completion gate. Introduce a reusable native case-task engine with durable assignment, outcomes and explicit recovery; this is one coherent coordinator → team worker → parent completion journey. Alternatives are catalogue orchestration and maintenance-window checks; those depend on shared tasks and change planning respectively.

Official Brazil sources retrieved 2026-11-18: https://www.servicenow.com/docs/r/build-workflows/workflow-studio/create-task-activity.html documents assigned task creation, predecessor start rules and waiting for completion; https://www.servicenow.com/docs/r/it-business-management/project-management/c_ProjectTasks.html distinguishes parent/child structures and several dependency types. The native contract below implements one-level case-owned tasks and finish-to-start dependencies. Nested project schedules, other dependency types, duration/resource/cost rollups, automatic state propagation and vendor task-table/API wire compatibility remain missing P1.

Contract before editing: schema 55 stores a revisioned task plan per parent record and at most 100 task rows, each with stable ID, ordinal, summary/instructions, current group/assignee, queued/working/complete/cancelled state, required flag, predecessor IDs, outcome, administrative note and revision. Tasks are separate native workflow objects under their parent's live record/field access, not generic record-table extensions. Current admin/agent staff and parent description/state access are required. A coordinator with parent update permission first selects a completion state from the schema, then creates/revises queued tasks. The chosen state and terminal schema states cannot be entered while a required task is incomplete; shared persistence enforces this for ordinary APIs and migration paths. Creating or changing work on a completed parent fails. Parent deletion requires all tasks terminal, then cleans task data atomically.

GET/POST /api/openservice/records/{table}/{id}/work-tasks and equivalent /record routes expose plan configuration, task creation, queued-task revision, claim, completion, cancellation, administrator requeue and explicit requirement waiver. Payloads have exact operation-specific keys and integer revision/record_revision; configured plan revision guards configuration/create, task revision guards task actions. Summary max160, instructions/outcome/reason max4000; required Boolean; dependencies are unique IDs, at most20, from the same parent's earlier tasks. Ordinal ordering makes cycles impossible. A task cannot be claimed until every predecessor completes. Workers must retain current group membership and parent access; completion requires current assignment, with existing administrator override. Cancellation does not satisfy a required task or predecessor; an administrator can explicitly waive a requirement with a reason, and a coordinator can revise still-queued successors. Requeue recovers work from unavailable assignees. Structural changes touch the parent revision; progress uses task revision and current live parent authority. Every operation audits and persists through restart.

A permission-filtered paginated team-work queue provides fulfilment discovery. Browser forms use labelled groups, states and predecessors, no raw IDs; routes redirect after mutation. Tests must cover both engines, source absence, current membership/role/parent-field revocation, stale/invalid payloads, cross-parent/forward/duplicate dependencies, cancellation/waiver/requeue, parent transition/deletion bypasses, atomic rollback, restart/upgrade and desktop/mobile light/dark keyboard/axe flows. This does not count the existing one-team fulfilment engine as a new feature.

Review 2 confirmed and fixed two further policy cases: removing a parent's current state from its schema left tasks mutable, and an administrator denied read access to one table received a failing whole queue rather than an authorized filtered page. Unknown/no-outgoing-flow parent states now prevent task mutation, and table read policy is included before queue counting/pagination. Both regressions failed before their fixes.
