# Decision and delivery workflows

Open **Enterprise workspaces** for the staff tools. **Intake applications** in the sidebar opens published forms for requesters. The enterprise JSON API accepts the same operations as the workspace forms at `/api/openservice/enterprise/{area}/global`. A write and its related local records share a transaction. Operations that accept a revision require the current integer version shown by the workspace.

| Area | Operator journey | Current boundary |
| --- | --- | --- |
| Decision workflows | An administrator defines reusable approval or work procedures in Access policies. In Decision workflows, add ordered rows using `amount_at_least`, `risk`, `location`, or `default`. Simulate an input that selects each row and publish. Start an intake against a named release. Each run retains the selected decision, input, procedure revisions and steps. | Fixed input vocabulary. Consecutive stages join parallel steps. A requester can answer a response step. The worker expires runs at the workflow deadline when `WORK_ENABLED` is enabled. |
| Connector packages | An integration owner publishes a typed manifest. Administrators import its portable JSON contract and install it separately in test and production. Entra membership and Jira transition installations register a reusable action for Access policies. GitHub issue reads return the issue ID, title and update time. Credential rotation invalidates the stored binding until an administrator reviews and reinstalls it. | Fixed typed adapters. The GitHub reader allows 30 successful reads per installation per minute. Entra and Jira writes retain their existing destination readback, throttle and retry controls. Live qualification still requires approved tenant destinations and test records. |
| Intake applications | Define the app name, fields, confidential fields, fulfillment group and published decision workflow. A second admin compares and promotes a development draft to the test catalog. Rebase an out-of-date draft after comparing both configurations. Requesters fill in labeled fields. Team members retrieve their queue, read the private brief and append private notes. Rollback restores a prior release and preserves the case's original field definitions, group, release and running workflow. | Development and test share one OpenService installation. An app's case type is a versioned intake definition. Generic dictionary tables and cross-instance package transport are outside this builder. |
| Discovery | Submit a complete cloud, Kubernetes or asset snapshot. Bind observations to a common component and choose an authoritative source and resource for each of title, type and CI reference. Inspect the effective value and sequence. Correct a bind to change dependency traversal. A successful complete refresh marks missing observations retired. Failed refresh reports retain last-good evidence. | AWS ELB/RDS, selected Kubernetes objects, and complete JSON asset exports. The worker polls a reviewed connector at a configured interval of 1–10,080 minutes, rechecks the owner and credential binding, and preserves the last accepted map on failure. The collector publishes its complete snapshot at the configured path. Missing preferred facts remain visibly unavailable. |
| Pipeline changes | Register a pipeline identity, service CI, independent policy owner and low-risk threshold. Submit an artifact, tests, impact and rollback plan with a stable release ID. Submission creates a native change plan and moves the change to review. Low-risk approval uses the policy owner's current authority and native change controls. Other releases wait for an administrator. A deployment callback advances the change to implementation. A failure creates a linked incident and problem. Recovery retains the actual rollback and recovery evidence. | OpenService ingests pipeline callbacks. The pipeline runs the deployments and service checks. |
| Suppliers | Register separate security, legal and finance owners for a supplier. Record the assessment and contract obligations. The finance owner releases a named supplier's purchase against a funded project. A failed assessment blocks it. Expired passing assessments need a current dated exception. The regular purchase approval route enforces enrollment. Trace the release snapshot, budget commitment, invoices and settlement entries. | Enrollment uses the normalized supplier name. Legacy unregistered suppliers retain ordinary approval. Contract obligations and independent security assessments are recorded by their owners. |
| Telecom site orders | Bundle previously offered installation quotes for one customer and currency. Add configured catalog items with one-time or monthly pricing to each site. The customer accepts one revision, atomically creating a distinct native order, service case and installation task per site. A replay returns the same order. Activate one site independently, or quote and accept an additional charge at just one site. | Recurring charges are quote terms. Customer billing, network activation telemetry and termination amendments are separate capabilities. |
| Process mining | Select a stateful table, record filter and completion state. Compare two equal-duration UTC creation cohorts with an equal follow-up window for each case. Inspect state paths, repeated states, mean time per visit, first-completion time, reopen rates and the visible case IDs. | Up to 500 selected records. The filter uses current field values. A reopened case left the chosen completion state. Incomplete bounded histories are excluded and counted. Matched windows and filters support descriptive comparison. |
| Recovery exercises | Set recovery-time and recovery-point objectives for a mapped service and dependency. Start an exercise with a snapshot of its dependencies and on-call coverage. Named responders record task outcomes. Enter the restored timestamp and recoverable data point. A missed objective assigns corrective work to the on-duty primary. Verify it against a later passing exercise using the original plan version. | An exercise records team observations. Automatic fault injection, replication verification and paging a real provider are separate activities. |
| Agent supervision | Revoked grants and uncertain actions create durable investigations. A grant owner can name a human administrator as investigator. If that person is unavailable when a case opens, it routes to an eligible owner or another eligible administrator. An eligible human administrator can claim an open investigation whose owner is unavailable. The claim preserves its previous owner and reason. The investigator records evidence, and the grant owner receives reviewed native cases for reauthorization. For a native plan, renew the grant after investigation, review the outstanding steps, and authorize the replacement plan separately before execution. While an investigation is open, a connector can read its destination. After a readback the investigator can accept the observed result or explicitly authorize a new attempt on a discrepancy. Previously recorded notes are preserved. | The held-out evaluation covers native triage, fulfillment and recovery. Live SaaS qualification and a larger representative sample remain open. |

## Workflow authoring examples

In the browser, open a numbered step, choose **Reusable procedure** or **Requester response**, and enter its stage. Select the same stage for steps that run in parallel. Use the same procedure ID in both designs to reuse the approval. The API accepts the equivalent structure below.

```json
[
  {"response":"Confirm the receiving office","stage":1},
  {"procedure_id":"<approval procedure ID>","stage":2},
  {"procedure_id":"<equipment team procedure ID>","stage":3},
  {"procedure_id":"<workspace team procedure ID>","stage":3}
]
```

For legal intake, open each numbered field and choose its stable name, display label and visibility. The equivalent API input is `[{"name":"summary","label":"Request summary","visibility":"requester"},{"name":"brief","label":"Legal instructions","visibility":"confidential"}]`. A case snapshots its app release. A later promotion can assign a different fulfillment group for subsequent cases.

The asset collector accepts `python3 scripts/collect-service-inventory.py --sequence 42 assets --name fleet --file fleet.json`. Supply an export such as `{"complete":true,"assets":[{"id":"orders-db","name":"Orders database","type":"Database"}]}`. Serve that output at the path of an approved connector and configure **Schedule a complete inventory** in Federated service maps. Use **Inspect last good inventory** to see the next attempt, last status, retirements and last accepted sequence. The topology inventory operation also accepts a direct post. Report failed attempts to the mapping workspace with `failed_collect`, the same source and sequence, and a short diagnostic.

## Service-desk evaluation

The [frozen scenarios](../src/test/resources/service-desk-supervision-holdout.json) cover six approved jobs, three revoked grants and three stopped plans. The [captured model run](service-desk-supervision-holdout-results.json) records the raw proposal, effective decision, verified state, assigned investigation, write count, provider time and usage for each case. The harness uses the native plan executor and grant store with an isolated database savepoint per scenario. Costs are unpriced when provider rates are absent. Reproduce with a dedicated loopback Ollama listener at port 11459, model `gemma4:e2b-mlx`, and the following command.

```sh
OPENSERVICE_QA_OLLAMA=http://127.0.0.1:11459 OPENSERVICE_QA_HOLDOUT=1 OPENSERVICE_QA_SUPERVISION=1 ./mvnw -Dtest=WorkflowTest#deliveryDeskOutcomes test
```

The raw model selected the expected decision in 10 of 12 cases. It suggested execution in SUP-4 and stop in SUP-6, both revoked-authority cases requiring investigation. Authority checks produced the required handoff in both. The supervised run verified 12 of 12 final outcomes with zero unauthorized writes. Median model-response time was 1.77 seconds. Scores apply to these 12 synthetic cases.

The [named-investigator evaluation](service-desk-supervision-repeat-results.json) alternated two human administrators as the expected investigator. Each of the three revoked grants created exactly one open investigation assigned to the correct person. The supervisor verified all 12 outcomes with zero unauthorized writes. The raw model selected 10 of 12, with misses on SUP-4 and SUP-5. Median provider latency was 2.26 seconds. Both evaluations used the same 12 frozen cases.
