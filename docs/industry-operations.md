# Enterprise and industry workflow qualification

The enterprise browser workspaces and `POST /api/openservice/enterprise/{area}/global` accept the operations below. The API body includes `operation` and the fields shown in the workspace. For a versioned update, send the revision returned by the preceding read. The workspaces enforce the authenticated user's permissions on the server.

| Area | Operator walkthrough | Evidence and scope |
| --- | --- | --- |
| Connector recovery | In Packages, register a versioned action and its same-origin audit collection with `history_contract`. After a write loses its response, restart the worker and run `verify_effect` with the original job ID. | The job pins the action's history contract. The collection must independently attest completeness for this correlation ID. One distinct provider event records the applied outcome and a SHA-256 evidence digest. Incomplete or conflicting evidence leaves the outcome unresolved. A second admin configured a third action in the HTTP fixture. After the write lost its response, the test rotated the local connection, rejected incomplete, unrelated and multiple-effect histories, and recovered one effect without sending another write. Credential rotation and lost writes in designated Entra and Jira tenants still need provider audit exports. |
| Guided workspaces | Publish an intake app in Apps. Create review stages with owning groups, bind them and the displayed fields with `compose_workspace`, then open a submitted case with `guide_case`. Reviewers use `guided_queue` and `advance_stage` to record waiting, resumption and completion. Purchasing can link an order. | Purchase and HR apps can reference the same stage. Existing cases retain their original stages. The native form and group rules control disclosure of confidential answers. The browser authoring surface accepts field and stage lists. |
| Git releases | Export a package with `python3 scripts/promote-intake.py config.json --export app.json`. Review the file in Git, resolve conflicting edits, then set `git.repository`, the full `git.commit`, `git.path`, and the reviewed `sha256` in the deployment config. Run the same command without `--export`. | The pipeline compares the reviewed file with the published development version, maps destination groups and connections locally, runs the role tests and uses a second identity to publish. A restart reads the deployment receipt. The native rollback selects a prior release and preserves cases and local connections. Tests exercised a temporary Git repository and independent development, test and production stores. |
| Endpoint inventory | Enroll an existing discovered resource with `enroll_endpoint`, assign its reporter and optionally bind a seat with `endpoint_seat`. On the host, run `python3 scripts/endpoint-collector.py config.json --every-minutes 15`. In Mapping, inspect `endpoint_status` for source observations, freshness and the shared CI. | Configuration uses `origin`, `auth_env`, `collector_id` and `tracked_software`. The collector reads host architecture, hostname and selected Windows registry or Linux package inventory. A successful authoritative retirement releases the originally assigned seat. Changed ownership or a changed seat goes to review. Linux package collection ran in a disposable container. Windows registry collection used a fixture. |
| Confluence policies | In Employee request assistant, bind each employee's delegated reader with `confluence_reader`. Use `index_confluence` for an approved page, audience group and service intent. Call `refresh_confluence` with the intent ID to reindex changed content, location and direct read-group IDs. The operation can be called by the operator's scheduler. | Each answer and confirmation requires current local membership, the bound upstream account and access to the current page. A moved, edited, archived, inaccessible or deleted page cannot supply its stale citation. OpenService keeps the last index on refresh failure. Inherited access is checked through Confluence as the employee. Local transport tests cover the adapter. [Atlassian content restrictions](https://developer.atlassian.com/cloud/confluence/rest/v1/api-group-content-restrictions/) |
| Transaction reliability | In Mapping, define a service objective and a `transaction_rule` with the expected response text and maximum latency in milliseconds. Run `scripts/service-probe.py` at the registered locations using operation `transaction_sample`, the expected text and an independent location-health URL. Inspect `transaction_evidence` and the service budget at release review. | A slow HTTP 200 or incorrect body counts as a service failure when corroborated across locations. A failing location health check produces an unknown observation. Evidence includes the original measurements and rule revision. Replays preserve paging and budget totals after an objective owner publishes a different latency or content rule. The probe supports one bounded HTTPS GET per location. |
| Contractor repair | Approve two contractor groups and dispatchers, then use `offer_repair` on a native entitled repair. The winning dispatcher assigns a technician. Download the assigned visit using `python3 scripts/contractor-visit.py config.json visit.json --download TASK_ID`. The technician records completion offline and sends the same file with `--sync`. | The original customer signs online. The depot records the serialized return. Finance matches the contractor invoice to that repair and closes the native case task in the same transaction. Expired or reassigned offers and duplicate completions are checked. Settlement produces an OpenService ledger record. |
| Telecom circuits | From an accepted site bundle, register ports with their native CIs and capacities. Use `reserve_circuit` on each ordered site, then activate it when its entire path is healthy. Use `port_condition` to report interruption or recovery. | Capacity is reserved across the entire path in one transaction. Concurrent orders competing for the last unit produce one reservation. A shared link identifies active circuits, customer sites, case and entitlement references. A native CI outage records the interruption and close. |
| Dealer warranty | Register terms, dealer, independent reviewer and finance owner on a serial. The dealer files the failure date and claim reference. After repair authorization, enter parts and labor and register the depot return of the failed serial. The reviewer adjudicates the amount and finance issues the credit. | Terms at the failure date are preserved. A repeat under the original reference returns the earlier claim. A different reference with the same dealer, serial, day and normalized failure description is rejected. Credit retries retain the original ledger entry. A returned component cannot fund a second claim. The customer service page links the dealer to its own claim list and individual claim records. The credit is recorded in the local ledger. |
| Regulatory notices | In Audits, publish a notice with its source reference, effective date, and affected policy, supplier, application or control. Each item has a responsible owner, independent tester and requirement. Owners assess the impact and record changes. Testers enter the outcome and evidence. | Each revision preserves the reviewed terms, decisions, people and evidence. A correction reopens the items whose terms changed. `notice_assignments` exposes assigned work and `notice_history` reproduces the selected revision. Notice ingestion starts with an explicit API or browser submission. |

## Search evaluation

Thirty eligible synthetic employee questions and five expected handoffs covered IT, HR and procurement across six offerings. The native matcher completed eight eligible requests. Adding indexed policy content completed 21. Both configurations routed all five expected handoffs correctly and produced zero unauthorized citations in the sample. Nine eligible requests still failed with indexed content. SQLite and PostgreSQL agreed on outcomes. The fixture-based evaluation records every miss, processing latency and model cost. ## Live qualification

A live connector run requires designated Entra group and member IDs, a Jira issue and transition, rotatable test credential bindings, and read access to each provider's audit history. Record the pre-write state, rotate the binding, interrupt the response after the write, restart the worker and retain the independent provider event for reconciliation. The generic contract expects a complete collection with `correlation_id`, `complete`, and `events` containing stable `event_id` and `correlation_id` values. A provider-specific adapter or audit export must supply those records. The Entra and Jira audit reader runs as `python3 scripts/check-provider-effects.py observation.json` and returns the matching provider IDs, page count and completed query window. [Provider observation configuration](enterprise-platform-workflows.md)

Live search qualification requires an approved Confluence Cloud ID, page IDs, a publisher binding, employee-delegated reader bindings and a test group whose membership can be revoked. Capture the citation before revocation, recheck the same conversation and confirm that the pending action cannot execute. The current benchmark uses synthetic questions and controlled transport.
