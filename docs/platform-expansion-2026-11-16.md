## Operational contracts

All new browser writes use the existing authentication, CSRF and transaction boundaries. Existing administrator/agent/reader/requester roles remain. New application data migrations are transactional and run on SQLite and PostgreSQL.

`WORK_ENABLED=true` enables the platform worker; `WORK_POLL_MS` defaults to 1000 ms. Account email remains separately controlled by `DELIVERY_ENABLED`. A platform job has a submitting administrator and authentication revision, an owner-scoped idempotency key, encrypted payload, lease and retry state. Password/role/state changes invalidate its authority. Five unsuccessful attempts lead to a visible failed job; administrators can retry or cancel queued/failed work. Completed/cancelled jobs can be explicitly cleaned up after 30 days; acknowledgments permit automatic notification cleanup after 30 days. Do not treat network calls as exactly-once external effects: the implemented connector action is read-only.

`CONNECTOR_ALLOWED_ORIGINS` is a comma-separated exact-origin allowlist managed by the deployment operator. HTTPS is required outside loopback; HTTP loopback origins exist for synthetic contract tests. Redirects are refused and transport time/response sizes are bounded. Database credentials are encrypted under the application secret, so backup/restore must preserve that secret. This is application encryption, not a managed HSM/KMS vault or a guarantee against an administrator with both the database and secret.

`AI_ENABLED=true`, `AI_CONNECTOR_ALIAS`, `AI_MODEL` and `AI_ALLOWED_FIELDS` explicitly configure assistance. Default allowed fields are `short_description,description`. Configure an approved provider/model and examine the data policy before enabling it. The local adapter uses `/v1/chat/completions`; model/provider-specific support must be qualified. It supplies no tools, disables provider storage via the request flag, and never evaluates or writes returned text. The provider must independently honor its agreed retention policy.

An external identity source cannot automatically attach to an existing local username or promote an account to administrator. New accounts receive an unknown random password and require password setup through the established onboarding/recovery administration flow. Deprovisioning removes memberships and invalidates account access. The contract is not SCIM and does not authenticate users through an IdP.

Published knowledge is an explicit administrator decision to share a workspace-visible article with all authenticated requesters. Private/group-only source articles cannot be published. Draft edits do not alter snapshots; retirement removes the article from the published list. Deleting or restricting the source article also hides its published content.

SLA clocks copy the calendar at creation. Subsequent calendar edits do not reinterpret an existing clock. Business time uses timezone-local start/end instants, handles DST, and excludes specified weekdays/holidays. Breach time is detection time, not a reconstructed contractual deadline. Clocks are administrator-operated in this first slice; automatic task lifecycle rules remain separate.

## HTTP contracts

`/api/openservice/operations/{resource}` is an OpenService-native API, not a ServiceNow-compatible endpoint. Writes generally return `200` with a `result` object. Unsupported query parameters are rejected.

| Resource | Methods and input |
|---|---|
| `jobs` | GET safe inventory. POST `{kind,key,payload}`. Kinds: `notification` with `{username,message}`; `connector.read` with `{alias,path}`; `migration.step` with `{migration_id,token}`. POST `jobs/{id}` with `{operation:retry|cancel|cleanup}`. |
| `connectors` | GET alias/origin/revision only. POST `{alias,origin,token}` creates or rotates an alias. |
| `calendars` | GET inventory. POST `{name,calendar:{zone,start,end,days,holidays}}`; HH:mm same-day window; weekdays 1–7; ISO local holiday dates. |
| `clocks` | GET inventory. POST `{table,record_id,calendar,minutes}`. POST `clocks/{id}` with `{operation:pause|resume|complete}`. |
| `reports` | GET visible definitions. POST `{name,table,query:{field,group_by,q},shared}`. GET `reports/{id}` executes with current viewer rights. DELETE `reports/{id}` removes an owned report. Browser role write restrictions still apply. |
| `knowledge/{article_id}` | POST `{operation:publish|retire}` for a `kb_knowledge` record. GET `/api/openservice/knowledge` or `/knowledge` shows latest published snapshots to authenticated users. |
| `dependencies` | POST `{dependent,dependency,remove}` for configuration items. GET `dependencies/{asset_id}` returns visible impacted assets and a truncation flag. |
| `events` | GET latest events. POST `{key,asset_id,severity,summary}`; severity info/warning/critical. A repeated correlation key updates its existing asset event and increments occurrences. |
| `references/{table}` | GET first 20 visible ID/summary references; no unrestricted private-record lookup. |
| `provisioning` | POST `{source,external_id,username,role,active,groups}`; groups are local group record IDs; roles agent/reader/requester. |
| `audit-access` | POST `{user_id,enabled}` grants/revokes journal viewing independently of account administration. |
| `audit-checkpoint` | GET a SHA-256 chain commitment and event count for external retention; administrators and granted audit viewers only. |
| `password-policy` | GET policy metadata. POST `{minimum_length,source,version,digests}` atomically replaces the screened corpus. Digests are lowercase SHA-256 of whole NFC-normalized passwords. Operator-selected minimum is 15–128; maximum password length remains 1024. |
| `assist` | POST `{table,record_id,allow_external:true}` requests an enabled read-only provider draft. |
| `qualification` | GET non-secret configuration/queue diagnostics; not a production certificate. |

`GET/POST /api/openservice/me/notifications` lists only the caller's notifications and accepts either `{enabled:boolean}` or `{acknowledge:notice_id}`. `/account/notifications` offers the browser journey. `/admin/operations` exposes queue, connector and SLA operation controls.

Approval delegation is `POST /api/openservice/records/{table}/{record_id}/approvals/{approval_id}/delegate` with `{approver:username}` and a corresponding browser form. The reviewer cannot be the original requester, the current reviewer, an ineligible account or a reviewer already assigned to the same proposal.
