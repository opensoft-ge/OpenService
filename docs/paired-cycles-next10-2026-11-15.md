## Cycle 1 — OS-N10-01: scoped read-only integration keys

Base: `bf1f422d9624bc1e575f0b2feba187c0438db654`. ADOPT-08/09, OS-PARITY-03/08. Existing code supported Basic/browser authentication but no scoped credential. Alternatives: MFA/SSO remain higher-level identity work; reusable connector aliases depend on a separate secret store and outbound runtime. This slice provides a bounded inbound machine credential, not OAuth or a connector engine.

Contract: active non-admin API-only accounts can receive administrator-issued keys for one existing table, valid 1–90 days, with a 1–80-codepoint label and 20-key cap. Only digests persist. GET/HEAD on the unversioned Table API collection/record paths are allowed; every other operation fails closed. Existing table/record/field permissions still apply. Expiry, deletion, account deactivation, password replacement requirements and access-revision changes deny use. Admin-only API/UI issue/list/revoke paths protect changes with the existing CSRF and mutation-lock boundary. Secret appears only on issuance; list/audit contain no secret/digest. Schema 24 preserves existing accounts and records.

Acceptance: issuance and listing, anonymous/nonadmin denial, method/query validation, malformed/unknown/expired credentials, wrong table, denied writes/other endpoints, hidden records and unreadable fields, API-only and account-state prerequisites, invalid input boundaries, cap/revocation/repeat behavior, restart and rollback, SQLite/PostgreSQL, and real keyboard/light/dark/mobile UI.
