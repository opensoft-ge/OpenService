## Live qualification

For an operator-supervised Entra membership addition or Jira transition, preserve the output of `provider_attempt` in the packages workspace as the `attempt_journal` in the qualification configuration. Run `python3 scripts/check-provider-effects.py CONFIG.json` with a least-privileged tenant audit credential supplied through the environment. The verifier joins the target, time window, provider correlation, write process, observed lost response, and first successful readback from a different process to fresh provider history. It checks that different credentials were presented on the same connection. A provider secret-rotation record is additionally necessary to attribute the difference to administrative rotation. An absent or ambiguous audit record cannot establish exactly one effect.

Intune verification supports a maximum last-sync age. Confluence verification can require the same delegated employee to retain access to a separate control page while losing access to the designated policy. Qualification still needs designated Entra and Jira records, an enrolled Windows/Intune fleet and a Confluence site with employee and indexing identities. No external production or tenant writes were made in this pass. [Provider scope and existing qualification procedure](qualification-and-service-quality.md)
