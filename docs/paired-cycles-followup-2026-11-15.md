Requested batch: ten sequential `open-service` + `qa-qc` cycles. Baseline `18bd0665ee446866feaedc603c4c59300174ad03`, clean `main`. Commits use `opendevbot`; no co-author trailers, pushes or deployments. This report is separate from the earlier twenty-cycle batch.

Each cycle fixes its review base at that cycle's starting commit, reviews the whole accumulated diff, repairs confirmed defects, then requires a clean review and `sh scripts/verify.sh` with `JAVA_HOME` set to the pinned Temurin installation. The exact skill checker covers every production Java file and both production JavaScript files. Template behavior is covered by real Chromium journeys, including desktop/mobile and both themes. No exclusions or lowered thresholds.

Stack rechecked 15 November 2026: [Spring Boot 4.1.2 supports Java 27](https://docs.spring.io/spring-boot/system-requirements.html); [Temurin 27.0.1.0.2+1 is GA](https://adoptium.net/en-GB/news/2026/10/eclipse-temurin-17021-21013-2505-2701-available). New implementation, tests and templates are written for this batch using existing project dependencies. Official documentation informs the behavioural scope; no vendor source, graphics or documentation passages are imported. Existing Apache 2.0 and third-party notices remain intact. ## Cycle 1 — private browser-session inventory (OS-F10-01)

**Base:** `18bd066`. **Scope:** ADOPT-08, OS-PARITY-08/10; blueprint A2 personalization and A4 authentication. The prior implementation exposed only all-browser revocation and had no per-session inventory.

**Feature:** schema 21 stores random public IDs and SHA-256 hashes of servlet session IDs, account/revision, sign-in/last-activity/absolute-expiry timestamps. Successful sign-in registers one entry and replaces a prior entry for the same cookie. Logout deletes it. Authenticated cookie use checks identity, revision, clock bounds, 30-minute idle and eight-hour absolute expiry and updates activity; missing pre-upgrade entries fail closed. Heartbeats commit before business-write locks. `GET /account/sessions` and `GET /api/openservice/me/sessions` expose only the caller's valid entries, a current-browser marker, UTC times and `truncated`; newest 100 rows maximum. Unknown queries/methods fail. Basic credentials do not create a browser entry. Existing sign-out-all and credential/role revocation continue to invalidate entries through account revision.

**Acceptance:** independent cookie jars, identity isolation even with a different Basic principal, hashed-only persistence, repeated-login replacement, logout removal, idle/absolute/future-clock boundaries, missing registration denial, durable inventory reinitialization, upgrade rollback/replay on SQLite and PostgreSQL, API method/query rejection, bounded output and keyboard/axe/overflow browser checks in both themes.

**Limits:** inventory is not distributed servlet storage or proof a browser is still open. Closed browsers and entries from an application restart remain until idle/absolute expiry; the page explains this. No IP address or user-agent collection, individual termination, session extension or automatic concurrency limit in this slice. An overflow is visible and all-browser revocation remains available.

**Discovery:** [Brazil active sessions](https://www.servicenow.com/docs/r/platform-security/identity/active-sessions.html) and [Brazil session administration](https://www.servicenow.com/docs/r/platform-administration/user-administration/c_ManageUserSessions.html), updated 10 September 2026, retrieved 15 November 2026, support session visibility/termination as reusable foundations. [OWASP session guidance](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html), retrieved the same day, informs local lifecycle boundaries. Newly tracked OS-DISC-SESSION-LIMIT: [Brazil concurrent session limits](https://www.servicenow.com/docs/r/platform-security/authentication/explore-lcs.html), missing P1/M1 under ADOPT-08/OS-PARITY-08; depends on session registry and administrator policy; acceptance must prove atomic oldest-session eviction and bounds under simultaneous sign-ins. Vendor feature requires its concurrent-session plugin; no such plugin compatibility is claimed. Candidate alternatives: scoped API credentials and SSO/MFA remain higher-level identity gaps. Rotating discovery attempted authentication/identity release-note pages (404); identifier-first routing remains unverified and merged into the existing SSO backlog, not claimed as supported. Next research: individual session termination and API authentication policy.

**QA ledger:** review 1 corrected heartbeat-row/advisory-lock inversion before gates and made schema creation replay-safe; targeted tests passed after fixing a checked-exception compilation omission. The new session-upgrade fixture follows the same convention.
