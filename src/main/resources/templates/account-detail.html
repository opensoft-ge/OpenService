Account access

Making an account inactive blocks sign-in and API access and signs out its browsers on their next request. Records and history remain available. Reactivation requires a fresh sign-in.

Changing a role signs out this person’s browsers on their next request. Basic API access uses the new role immediately. Staff roles can read workspace-visible records subject to field permissions. Requesters can access only their own submitted requests. Private records require explicit access.

Access mode

API-only accounts cannot sign in to the workspace or open authenticated browser pages. Their role and record permissions still apply. Changing mode revokes existing sessions and security links; the final active browser administrator is protected.

Basic authentication

Control whether this account can use a username and password in an HTTP Authorization header. Browser sign-in and browser-authenticated API requests remain available. Role and record permissions still apply. Changes sign out existing browsers and revoke security links. API-only accounts can switch to scoped keys through Manage API keys. The explicit replacement action blocks Basic authentication and issues a new key; the ordinary control requires restoring browser access before blocking Basic.

Assisted password recovery

Verify the person’s identity through your agreed support process before sharing a link. Links last 15 minutes and work once. Issuing a new link replaces the previous one; it does not change the current password or sign the person out. Confirm with your own administrator password; repeated incorrect confirmations temporarily block verification for up to five minutes.

This recovery link is shown once. Share it privately with the verified account holder.
